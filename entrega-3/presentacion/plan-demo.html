1. El formato: primero la presentación, después una sola demo

Recomendación: 15 minutos de diapositivas, después 8 a 10 minutos de demo continua y al final las preguntas. Conviene esto y no intercalar demo entre diapositivas por tres razones: no se cambia de pantalla diez veces, si la demo se traba no arrastra a la presentación, y la demo puede seguir la consigna punto por punto como una lista de control que el docente va tachando.

3. Preparación: el día anterior

  • Push de la rama entrega-3 a GitHub y verificar que el pipeline de Actions quede en verde (sin push, el punto de CI no se puede mostrar).
  • Probar la IA con una API key real (ver 5.2). Si sale "origen":"modelo", queda demostrado; si no hay key, se muestra el fallback y se dice tal cual.
  • Ensayar la compra desde la tienda (D1) con la cuenta de cliente de prueba. Es lo único que todavía no se vio en un navegador.
  • Correr todo una vez: ./mvnw verify, ./scripts/levantar-wildfly.sh y ./scripts/probar-resiliencia.sh.
  • Ensayar la presentación entera con cronómetro: 15 minutos.
  • Exportar la presentación a PDF y PPTX (Share › Export) y guardarla en un pendrive: plan B si no hay internet.
  • Grabar un video corto de la demo funcionando (plan B si algo falla en vivo).
  • Compartir la presentación con el grupo (está privada hasta que se comparta).

  • Cargador enchufado, notificaciones silenciadas, letra de la terminal grande (Ctrl + + varias veces).

  • Postman abierto con la colección entrega-3/GOMARKET-checkpoint3.postman_collection.json importada (alternativa visual al script).

Ojo con la carpeta. Los scripts están en ~/Materias/dapii/desarrollo-app-ii-tpo/scripts/. Si se corren desde ~/Materias/dapii sale “No such file or directory”. Siempre hacer cd ~/Materias/dapii/desarrollo-app-ii-tpo primero.

Para el timeout de 5 s: un proveedor lento no se puede forzar en vivo, así que se muestra el test que lo prueba (tarda unos segundos):

./mvnw -q -o test -Dtest=GatewayIATest      # 10 tests en verde, incluido el de timeout

Abrir GatewayIA.java en la constante PRESUPUESTO_MS = 5_000 y el bloque catch (TimeoutException) si piden ver el código.

D5 · Se apaga el broker y no se pierde nada · Fol · 2:00

./scripts/probar-resiliencia.sh --broker
# deja un pedido en la cola con el consumidor frenado e imprime su id y un curl listo

kill -9 $(pgrep -f jboss-modules.jar)     # se cae todo: WildFly y su broker Artemis
# en la TERMINAL 1:
./scripts/levantar-wildfly.sh             # vuelve (compila y arranca en ~30 s)

# en la terminal 2, el curl que imprimió el script:
curl -s localhost:8080/ecommerce/api/v1/pedidos/<id> -H 'Authorization: Bearer <token>'
# → "estado":"PROCESADO": el mensaje persistente sobrevivió al kill -9

Qué decir: “Frenamos el consumidor para que el mensaje quede esperando en la cola; matamos el proceso sin darle tiempo a nada; al volver, Artemis lo tenía en disco y el MDB lo procesó.”

6. Si algo falla (plan B)

FallaQué hacer
WildFly no levantaMirar la terminal 1; casi siempre es el puerto 8080 ocupado por un WildFly anterior: kill -9 $(pgrep -f jboss-modules.jar) y volver a levantar. Si no se arregla en un minuto, pasar al video grabado y a entrega-3/evidencias/.
No hay internetTodo funciona igual salvo la IA real: el gateway responde con el fallback ("origen":"reglas"). Decirlo: “justamente para esto está el fallback”. La presentación, desde el PDF exportado.
La IA responde "motivo":"error"La key es inválida o no hay saldo. Es el fallback funcionando: mostrarlo como tal.
429 “muchas búsquedas con IA”Es el límite de 30 consultas por minuto por IP. Esperar los segundos que dice o mostrarlo como otra protección del gateway.
La compra desde la tienda fallaVerificar que se ingresó con la cuenta de prueba después de levantar el servidor (el token se pide al ingresar). Plan B: mostrar la compra con el script (D3), que hace la misma secuencia HTTP.
El CI está rojo o no corrióMostrar ./mvnw verify en vivo (tarda unos segundos) y el reporte de JaCoCo local.
Se acaba el tiempoPrioridad: D5 (kill -9), D3 (script) y D1 (compra). D6 y D7 se pueden decir en una frase.
