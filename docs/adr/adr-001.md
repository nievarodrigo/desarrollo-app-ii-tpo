# ADR-001 · Encapsular estados del pedido

Estado: implementado localmente, 06/11/2026; deriva de la propuesta del 23/10. Contexto: Pedido usaba un String y el repositorio aceptaba cambios arbitrarios. Las carreras y reentregas podían dispersar reglas entre servicio y MDB.

Decisión: EstadoPedido.aplicar(EventoPedido) y objetos de estado inmutables en EstadosPedido. Pedido.transicionar() devuelve un nuevo pedido conservando identidad, ítems y total. PedidoEnMemoria.aplicar() utiliza computeIfPresent. El JSON mantiene estado como texto; setEstado queda para hidratación, no para decisiones de negocio.

Alternativa: setters libres y condicionales en cada consumidor; descartada por permitir cambios inválidos. Un enum con una tabla sería más breve, pero State expresa comportamiento por estado como pide la actividad. Consecuencias: más objetos y pruebas explícitas; no aporta persistencia ni idempotencia durable por sí mismo.

Verificación: seis pruebas JUnit para procesamiento/duplicado, reintento de envío, rechazo, aceptación de reserva, estado desconocido y mensaje tardío. Archivos en pedido/domain y PedidoStateTest. No ejecutadas aquí por falta de JDK/Maven; no se afirma compilación.
