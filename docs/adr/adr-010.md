# ADR-010 · Puertos para repositorio y mensajería (inversión de dependencias)

Estado: implementado, 12/11/2026. Contexto: la clase 12 (A3) señaló que `PedidoService` y `ProcesarPedidoMDB` dependían de `PedidoEnMemoria` (un detalle), y el service mezclaba negocio con la API de JMS.

Decisión: `PedidoRepository` (guardar/obtener/aplicar) y `PublicadorPedidos` (publicar) son interfaces; `PedidoEnMemoria` y `PublicadorPedidosJms` las implementan. El service y el MDB reciben las interfaces. `ProcesarPedidoMDB.procesar(String)` separa la lógica del tipo `Message`.

Consecuencias: el flujo completo (login, pedido, cola, MDB, State) se prueba con JUnit sin servidor, reemplazando la cola por una lista en memoria; cambiar a una base de datos no toca al service. Un mensaje cuya transición es inválida (por ejemplo, pedido cancelado antes de procesarse) se descarta con aviso en el log en vez de reentregarse sin fin. Sigue pendiente la durabilidad (ADR-007, outbox/inbox).
