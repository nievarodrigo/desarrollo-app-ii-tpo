# ADR-009 · REST/JSON en toda la integración; no se usa SOAP

Estado: decidido, 12/11/2026. Contexto: el diseño de la entrega anterior planteaba un adaptador SOAP hacia un "inventario legado" (`entrega-diseno/contratos/inventario-legado.wsdl`, `soap-request.xml`, `soap-fault.xml`). Nunca se implementó en `src/`.

Decisión: GOMARKET es un e-commerce con front web y mensajería interna: todo es REST/JSON (JAX-RS) más JMS para lo asíncrono. No hay JAX-WS, WSDL ni clientes SOAP en el código. Si se integra un inventario externo, se hará con un cliente HTTP/JSON detrás de un puerto (misma idea que `PublicadorPedidos`). Los errores de negocio se devuelven como Problem Details (RFC 9457) con códigos HTTP (409 por stock/estado, 404, 401, 403, 429); el equivalente del `Fault` de SOAP.

Por qué REST y no SOAP: el front es JavaScript y consume JSON de forma nativa; REST usa HTTP tal cual (cache, códigos, curl); SOAP agrega XML, WSDL y generación de clientes que no necesitamos; SOAP sólo tendría sentido si el sistema externo lo exigiera, y acá no hay ninguno real.

Consecuencias: los contratos SOAP de `entrega-diseno/contratos` quedan como material histórico de la entrega anterior y no se usan en el código. Si aparece un ERP que sólo hable SOAP, se lo aísla en un adaptador.
